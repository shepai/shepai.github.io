Tactile sensing in soft simulation tutorial

Posted 06/10/2026

MuJoCo (Multi-Joint dynamics with Contact) is a physics simulation engine widely used in robotics research for modelling complex interactions between bodies, joints, and contacts in real time. We explored this in a previous tutorial for the development of soft bodied simulations. In this tutorial we will be exploring the tactile gyms I have created.

These gyms provide TacTip, or TacTip style, optical tactile sensing to simulated robots. Constructing real robots with tactile sensors is costly, and it is not simple to run reinforcement learning on physical hardware: training needs millions of interactions, and soft sensors wear out. This is why we work in simulation. However, making a simulation of a soft sensor work well enough to be useful is not trivial, so the gyms package that work up for you. Each gym follows the standard Gymnasium interface, so it should slot into existing reinforcement learning code.

Each gym has a GitHub link and associated setup instructions in the GitHub readme. I will only cover installation briefly, as the repositories keep the up to date version.

Contents

How the simulated TacTip works

The TacTip is an optical tactile sensor. A soft, silicone dome has rows of small pins on its inside surface, and a camera looks at the pin tips. When the dome touches something, it deforms and the pins move, and the camera sees those pin displacements. The tactile signal is the image of the pins, rather than a force reading.

In simulation, the dome is a mesh of points joined by a flexible structure so that it behaves like soft silicone (see the soft body tutorial for how this was built). A virtual camera inside the dome renders the pins each step, which gives us an image observation just like the real sensor would. The simulated sensor is based on my earlier robot foot repo.

TacTip gym

The TacTip gym provides a TacTip sensor on various robot bodies. It is also simple to attach to your own robotic design. This gym is all about attaching soft bodied sensors onto robot chassis, so that we can gather tactile information in a physics simulation.


Installation

You will need Python with MuJoCo installed (see the MuJoCo setup pages for your operating system). Clone the repository, move into the folder, and install it in editable mode: 
git clone https://github.com/shepai/TacTip-gym.git
cd TacTip-gym
pip install -e .
Editable mode (-e) means that any changes you make to the source, such as editing the sensor parameters, take effect without reinstalling. You will also want OpenCV (pip install opencv-python) if you plan to view the tactile images.

Available environments

Importing the package registers each environment with Gymnasium, so you can create one with gym.make.
EnvironmentDescription
RandomTac-v0A standalone TacTip with boxes of random placement. This is the simplest environment, and has no controllable actions as it is just the basic sensor.
RobotArm-v0A TacTip mounted on the end of a robot arm that can move around and touch objects.

Your first simulation loop

Start by creating the environment. Note that the import of tactip_mujoco_gym is needed even though it is never called directly, as it triggers the registration. 
import time
import gymnasium as gym
import tactip_mujoco_gym  # triggers register()

import mujoco.viewer

env = gym.make("RandomTac-v0")
model = env.unwrapped.model
data = env.unwrapped.data
The model and data objects are the underlying MuJoCo model and simulation state. We pull them out of env.unwrapped so that we can hand them to the MuJoCo viewer.

Then we open a viewer window to visualise the simulation. Inside the main loop there are three jobs: choose an action (what you want the robot body to do), step the environment (pass the command through and make a physics step), and sync the viewer so the window updates. 
with mujoco.viewer.launch_passive(model, data) as viewer:
    while viewer.is_running():
        # RandomTac has no actions that change anything, so we pass an empty list
        obs, reward, terminated, truncated, info = env.step([])

        # Sync viewer with updated physics
        viewer.sync()

        # Reset if the episode ends
        if terminated:
            obs, info = env.reset()
The examples folder in the repo contains complete versions of these scripts, which are a good starting point to copy from.

Viewing the tactile image

The observation is a dictionary, and the tactile image lives under the "image" key. You can show what the sensor camera sees by adding the following inside the loop: 
import cv2

img = obs["image"]
cv2.imshow("sensor_cam", img)
cv2.waitKey(1)
# small sleep so it doesn't max out the CPU
time.sleep(env.unwrapped.model.opt.timestep)
When a box presses into the dome, you should see the pin pattern distort around the contact point. That distortion is the tactile signal that a policy or classifier would learn from.

The robot arm environment

RobotArm-v0 gives the sensor a body that you can actually move. Its spaces are:
SpaceTypeShapeDescription
ObservationDict{"image": (H, W, C)}Tactile sensor image observation
ActionBox(6,)Six continuous motor commands
Because there is a real action space, we can now sample random actions and pass them in: 
env = gym.make("RobotArm-v0")
model = env.unwrapped.model
data = env.unwrapped.data
obs, info = env.reset()

with mujoco.viewer.launch_passive(model, data) as viewer:
    while viewer.is_running():
        action = env.action_space.sample()   # six random motor commands
        obs, reward, terminated, truncated, info = env.step(action)
        viewer.sync()

        if terminated or truncated:
            obs, info = env.reset()
Replace env.action_space.sample() with your own controller or a learned policy to do something useful.

Adding the sensor to your own robot

The sensor is defined in the MuJoCo model files in the repo's assets folder. To put a TacTip on your own chassis, the general process is:
  1. Copy the sensor definition from the assets folder into your own robot's model folder, keeping the mesh files next to it.
  2. Include it in your robot's XML, and attach it to the body where you want the sensor (for example the end of a limb or the rim of a wheel).
  3. Position the sensor so the dome faces outwards and has room to deform without starting inside another geometry.
  4. Keep the sensor camera inside the dome, as this is what produces the tactile image.
  5. Register your own environment that loads the new model, copying the observation handling from the existing environments.
If the sensor explodes or jitters on first load, reduce the simulation timestep slightly or check that nothing is overlapping at the start.

Tactile ball gym

The tactile ball gym applies the principles from the TacTip gym environment, but on an actual moving chassis. This chassis uses two TacTips as wheels, with a central body holding the electronics and cameras. The aim of this simulation is to explore whole body tactile sensors, where the entire surface of the robot is sensing as it rolls. This gym has the one chassis, but across different terrains and environments.


Installation

The gym lives in a subfolder of the repository, so install it from there: 
git clone https://github.com/shepai/tactile-ball-robot.git
cd tactile-ball-robot/ball-gym
pip install -e .

Running it

The ball gym follows the same pattern as the TacTip gym: import the package to register it, make the environment, and step it in a loop.

import ball_gym   # TODO: replace with the real package name

Training a policy with tactile observations

Since both gyms follow the Gymnasium interface, you can use standard reinforcement learning libraries. The main thing to be aware of is that observations are images, so you need a policy network that can process them (a small CNN encoder is a good start). With Stable-Baselines3, for example, you would use a MultiInputPolicy for the dictionary observation: 
from stable_baselines3 import PPO

model = PPO("MultiInputPolicy", env, verbose=1)
model.learn(total_timesteps=100_000)
Tips that tend to help with tactile images:
  • Downscale the image (for example to 64x64) or convert to grayscale to speed up training considerably.
  • Run without the viewer during training, as rendering a window slows the simulation down a lot.
  • Use several parallel environments to collect more tactile data per second.

Troubleshooting

  • NameNotFound error when calling gym.make: the package was not imported, so the environments were never registered. Make sure import tactip_mujoco_gym comes first.
  • Viewer window does not open: check your MuJoCo and graphics setup. On macOS the viewer may need to be launched with mjpython.
  • No tactile image window appears: make sure OpenCV is installed, and that cv2.waitKey(1) is called every loop so the window refreshes.
  • Simulation runs slowly: soft bodies are expensive. Close the camera window, reduce the image resolution, or train without the viewer.
