Environments¶

The task catalogue, the shared base classes and every robot. Each task is created with gym.make(<task id>, ...); the classes below are what it builds.

.. py:module:: tactip_mujoco_gym.envs

The task catalogue. Every task is a Gymnasium environment:

::

       env = gym.make("TacArm-peg", obs_modes=["tactile"])          # after import tactip_mujoco_gym
       env = gym.make("tactip_mujoco_gym:TacArm-peg", ...)          # imports the package itself

   `python -m tactip_mujoco_gym list` prints this table; `... describe <task>` builds the task
   and shows every input it offers. Keyword arguments every robot accepts:

       obs_modes     inputs the policy gets: {"tactile": True, ...}, ["tactile", "vision"] or
                     "tactile+vision" (proprioception is always included)
       obs_format    "flat" (one vector) or "dict" (one key per input, for fusion networks)
       sensors       {key: readout spec}: change, add or remove sensor readouts
       sensor_xml    the sensor hardware mounted on the robot (default: the TacTip)
       overrides     {"CONSTANT": value}: any of the env's class constants, for this instance
       max_steps     episode length
   plus the task's own options below.

.. py:function:: list_tasks() :module: tactip_mujoco_gym.envs

{task id: summary} for every registered task.

Base classes¶

.. py:module:: tactip_mujoco_gym.envs.base

Shared MuJoCo + Gymnasium plumbing for the tactip environments.

::

   TactileGymEnv  - loads the model and owns the observation pipeline: which inputs are
                    selected (obs_modes), the sensor readouts that compute them (sensors), the
                    places on the robot the sensor hardware is mounted (sensor_mounts) and the
                    flat / dict observation format. The original constructor signature
                    (xml_subpath, obs_dim, action_dim) and the legacy reset/step/_get_obs are kept
                    so RandomTac behaves exactly as before.
   TaxelMixin     - adds the event-based tx_* taxel input ("events") and its API.

   Observation inputs
   ------------------
   Proprioception (the robot's own state) is always included. On top of it, any combination of

       task inputs   computed by the task itself: "privileged" (true task state: object pose,
                     goal vector, ...) and, for the humanoid, "object"
       sensor inputs computed by readouts (sensors/), one per key. Defaults on every robot:
                     "tactile"        TacTip marker displacements and their change (all mounts)
                     "tactile_image"  the camera inside each TacTip
                     "vision"         the robot's camera (VISION_CAMERA)
                     arm only: "events" (taxel events on the objects)

       gym.make("TacArm-peg", obs_modes={"vision": True, "tactile": True})   # missing keys = off
       gym.make("TacArm-peg", obs_modes=["vision", "tactile"])               # same, as a list
       gym.make("TacArm-peg", obs_modes=["tactile"], sensors={"tactile": {"clip": 10}})
       gym.make("TacArm-peg", obs_modes=["force"], sensors={"force": MyForceReadout()})
       env.unwrapped.set_obs_modes({"tactile": True})     # a dict / list is a full selection
       env.unwrapped.set_obs_modes(vision=True)           # keywords change only those keys

   sensors={key: spec} replaces a default readout, tweaks it ({"width": 96} keeps the type),
   adds a new key, or removes one (None). Specs: a registered name, "module:Class", a dict
   {"type": ..., **kwargs} or a Sensor instance (copied per env). See sensors/base.py.

   The selected parts are concatenated into one flat vector (obs_format="flat", default), in the
   order proprio, task inputs, sensor inputs, or kept under their own keys (obs_format="dict"),
   ready for a fusion network (SB3: MultiInputPolicy, or vt_encoders.VisuoTactilePolicy).

   Every change rebuilds env.observation_space, so call these before wrapping the env in a
   VecEnv / VecNormalize, or pass obs_modes=... through env_kwargs (see RL_BASE.run).
   The earlier privileged=True/False argument and set_privileged() still work:
   True = privileged only, False = tactile only.

   overrides={"NAME": value} sets any of the env's UPPER_CASE class constants on this instance
   (e.g. {"TIP_R": 0.03, "VISION_WIDTH": 96}), for config files and sensor swaps.

.. py:class:: TaxelMixin(*args, **kwargs) :module: tactip_mujoco_gym.envs.base

Bases: :py:class:~tactip_mujoco_gym.envs.base.TactileGymEnv

Event-based readout of the touch-sensor grid made by add_events.py (tx_* sensors), as the “events” input (readout: sensors/taxels.py).

::

   A taxel emits an event when its force has changed by at least EVENT_THRESHOLD newtons since
   the last event on that taxel (or since reset); the reference level is then set to the
   current force, like a neuromorphic sensor. A steady load produces no events.

       env.unwrapped.set_event(True)     # = set_obs_modes(events=True): one value per taxel,
                                         # the signed event count since the previous step
       env.unwrapped.get_events()        # raw events, rows of [taxel_index, polarity, time]

   While events are off and every sensor in the model is a taxel, MuJoCo's sensor evaluation
   is switched off entirely (thousands of touch sensors are a big part of the step cost).

  Events since the last call, as an (N, 3) array: [taxel_index, polarity, time].

  Current normal force on every taxel (n_taxels,).

.. py:method:: TaxelMixin.taxel_positions() :module: tactip_mujoco_gym.envs.base

Arm (Unitree Z1)¶

.. py:module:: tactip_mujoco_gym.envs.robot_arm

Tactip arm tasks.

::

       TacArm-hill   Incline         intercept a ball rolling down a ramp, then push it to the top
       TacArm-peg    Peg             start touching a cylinder, push it into the hole
       TacArm-shape  ShapeInsertion  start touching a shape, identify it, push it into its own hole
       TacArm-edge   Edge            start touching the top edge of a block, follow it round (CCW)

   Every task accepts:
       obs_modes={"vision": bool, "tactile": bool, "privileged": bool, ...} or a list of names
                 (see base.py; default: privileged only; missing keys count as False). Inputs:
                 privileged, tactile, tactile_image, vision, events, plus any added by `sensors`
       obs_format="flat" | "dict"     one long vector (default) or one key per input
       sensors={key: spec}            change / add / remove readouts (see base.py, sensors/)
       sensor_xml=None                sensor hardware on the arm: None = the TacTip written into
                                      the scene; a registered name ("tactip"), a standalone MJCF
                                      file or an MjSpec swaps it (see sensors/models.py)
       sensor_stiffness=1.0           scales the sensor's joint / tendon stiffness and damping
       overrides={"TIP_R": 0.03}      set class constants on this instance
       events=True/False              append tx_* taxel events (= "events" in obs_modes)
       privileged=True/False          earlier shortcut: privileged only / tactile only

   Swapping the sensor: the built-in TacTip (every body under SENSOR_PARENT, with its tendons,
   equalities and contact excludes) is cut out of the scene and the chosen sensor is attached to
   SENSOR_LINK, turned and moved so its tip is where the TacTip's tip was. The arm's ee_site
   (the point the controller moves) and hand camera stay where they are. Constants that depend
   on the sensor's shape (TIP_R, PUSH_Z, Incline.TIP_H) may need `overrides`; check_envs.py
   reports them for a new sensor.

   Control (shared by all tasks)
   -----------------------------
   action in [-1, 1]  ->  low-pass filtered velocity command (ACTION_SMOOTHING)
       -> Cartesian tip displacement (ACTION_SCALE metres per step at full command)
       -> commanded tip target, which may not run more than LEASH ahead of the measured tip
          (no wind-up when blocked) but is never dragged back to it (no gravity-sag ratchet)
       -> differential IK (damped least squares) warm-started from the previous *command*,
          never from the measured joints, so the arm can't drift or flip IK branches
       -> joint targets with velocity + gravity feed-forward, interpolated over FRAME_SKIP steps.

   Rewards
   -------
   Per step, roughly in [-1, 1]: mostly *progress* made this step (object toward its hole, ball up
   the slope, distance along the edge) plus small closeness terms. All terms depend only on the
   state (no hidden stage counters). Paying for progress rather than proximity matters: with a
   static closeness reward, doing nothing out-scored noisy attempts and PPO learned to sit still.
   Success adds R_SUCCESS and ends the episode; unrecoverable failure adds R_FAIL and ends it.

.. py:module:: tactip_mujoco_gym.envs.surface_follow

TacArm-surface: slide the sensor along a wavy strip, keeping it pressed in by the same depth and (by default) square to the surface.

::

       env = gym.make("TacArm-surface", obs_modes=["tactile"])
       env = gym.make("TacArm-surface", wave="chirp", texture="patches")

   The strip (STRIP_LENGTH x STRIP_WIDTH, a heightfield) is redrawn every episode:

       wave     "uniform"  one sine: the same amplitude and wavelength all along
                "chirp"    wavelength and amplitude change steadily along the strip
                "multi"    two or three sines added (an irregular profile)
                "flat", "random" (default: one of the three waves), or a list to draw from
       texture  None (default, smooth), a dataset texture 1..20 all along (a uniform texture),
                "random" (one of TEXTURES all along), "patches" (a different one every
                TEXTURE_PATCH metres: a non-uniform texture), or a list to draw one from.
                Textures are the 3D Printable Tactile Dataset's at the printed scale
                (see textures.py; TEXTURE_SCALE scales their relief).

   The waves vary along the strip only, so square to the surface means pitching the sensor.
   The depth and the surface normal are measured from the wave (the surface the task asks to
   follow); a texture is relief on it that the sensor feels but doesn't have to trace.

   Control: the tip advances along the strip by itself (SPEED per step). Actions in [-1, 1]:
       follow_normal=True  (2) depth (tip up / down), pitch rate of the sensor
       follow_normal=False (1) depth only; the sensor stays vertical
   The depth to keep is set at the start: the sensor is lowered onto the flat start of the strip
   and pressed in by PRESS.

   Reward per step: closeness to that depth (W_DEPTH), sensor axis along the surface normal
   (W_NORMAL, follow_normal only), and progress along the strip while touching it (W_PROG).
   Success: reach the end of the strip. Fail: lift off by LOST_UP or press in LOST_DOWN deeper.

   privileged input: depth error (cm), sensor pitch, the pitch square to the surface, their
   difference, angle to the normal, the surface height 1, 2 and 4 cm ahead (cm, relative to
   under the tip), progress along the strip, touching.

Quadruped (Unitree Go2)¶

.. py:module:: tactip_mujoco_gym.envs.tactip_quadruped

TacQuad: a Unitree Go2 (MuJoCo Menagerie) with a TacTip on every foot, learning to walk stably on ground whose feel changes from tile to tile: friction, softness, bounce and bumps.

::

       env = gym.make("tactip_mujoco_gym:TacQuad-walk", obs_modes={"tactile": True})

   The model is built in code (MjSpec) every time the env is made, so go2.xml itself is never
   edited: the Go2 (assets/go2/go2.xml, or any go2.xml found under assets/), its foot spheres
   replaced by four prefixed copies of assets/sensor/tactip.xml (FL_, FR_, RL_, RR_; see
   sensor_tools.py), position-controlled joints, a head camera and a grid of heightfield tiles.
   Works with the MuJoCo Menagerie Go2 and the one in Unitree's unitree_mujoco repo.

   See the robot with its TacTip feet, or write it out as a standalone XML:
       python -m tactip_mujoco_gym.envs.tactip_quadruped --view
       python -m tactip_mujoco_gym.envs.tactip_quadruped --save go2_tactip.xml

   Observation inputs (obs_modes), as in the arm tasks; proprioception is always included:
       proprio     base angular velocity, gravity in the base frame, velocity command,
                   joint positions (minus the standing pose), joint velocities, previous action
       privileged  base linear velocity, base height, foot contact forces, friction and softness
                   under each foot, foot heights, a grid of terrain heights around the robot
       tactile     marker displacements of all four TacTips (mm) and their change since last step
       tactile_image  the cameras inside the four TacTips, stacked along the channels
       vision      the head camera (VISION_CAMERA = "headcam")
       + any readout added with sensors={...}; the four feet are env.sensor_mounts (FL, FR, RL, RR)

   Action: 12 joint targets, a in [-1, 1] -> standing pose + ACTION_SCALE * a, PD at KP / KD.
   Task:   follow a velocity command (forward, sideways, turn), resampled every few seconds;
           episodes end when the trunk touches the ground or the robot tips past 60 degrees.
   Terrain: N_TILES x N_TILES tiles of TILE metres. Every reset draws, per tile, a friction, a
           softness (contact time constant + impedance) and a damping ratio, and decides whether
           the tile is flat or rough (bumps and mounds). `terrain_level` (0..1) scales how
           extreme they get, and with curriculum=True it rises when the robot copes and falls
           when it doesn't. Tile colour shows the feel: blue = slippery, red-brown = grippy,
           paler = softer. Flat tiles are boxes and rough tiles heightfields (the TacTip pins
           collide with a box several times faster).

   Feet:   "tactip" four TacTips (slow: ~150 bodies of sensor); "proxy" one sphere per foot
           with the TacTip's size, reach and mass (same leg geometry, much faster: train a
           privileged teacher on it); "rigid" the Go2's own feet.

Humanoid (RB-Y1) and gripper¶

.. py:module:: tactip_mujoco_gym.envs.tactip_humanoid

TacHumanoid: a wheeled humanoid (Rainbow Robotics RB-Y1, MuJoCo Menagerie) whose two hands are TacTips. It picks up an object by squeezing it between the two sensors, carries it to a target on the table and puts it down.

::

       env = gym.make("tactip_mujoco_gym:TacHumanoid-pick", obs_modes={"tactile": True})

   Objects (one per episode, drawn from OBJECT_NAMES): five soft ones (cube, brick, ball, egg,
   cylinder: a core covered in spring-loaded pads that dent where they are pressed) and five rigid
   ones (box, cylinder, sphere, capsule, prism). Every episode randomises the object's stiffness
   (soft: foam .. firm rubber; rigid: rigid), mass, surface friction, position and yaw, and where
   the target is. Gripping too lightly lets heavy or slippery objects slide out; squeezing too
   hard crushes soft ones.

   Robot: the base drives like a differential-drive platform (forward speed + turn rate); the
   6-joint torso and the head hold a fixed pose leaning over the table. Each TacTip is mounted
   like a palm, on the side of the wrist, so the forearms come down from above while the two
   sensors face each other; each tip is moved in Cartesian space by inverse kinematics.

   Actions (action_mode):
       "bimanual"     (default, 7) base forward speed, turn rate, grasp centre x, y, z (robot
                      frame, velocity), grasp width (velocity: negative closes the hands),
                      grasp yaw (turn rate of the line between the hands, up to +-0.8 rad)
       "independent"  (9) base forward speed, turn rate, left tip x y z, right tip x y z, grasp
                      yaw

   Observation inputs (obs_modes), as in the other tasks; proprioception is always included:
       proprio     both tips in the robot frame, how far each lags its command, the smoothed
                   action, base speed and turn rate, the target relative to the robot, and
                   whether the object has been lifted yet
       object      what a camera-based object tracker would give: the object's position
                   (relative to the hands and to the target), velocity, orientation, size, shape
                   and height above the table
       privileged  "object" plus what touch has to work out: stiffness, mass, friction, how
                   squashed it is and the grip force on each hand
       tactile     both TacTips' markers: displacement from rest and change since last step (mm)
       tactile_image  the cameras inside the two TacTips, stacked along the channels
       vision      "headcam" on the head, looking down at the table
       + any readout added with sensors={...}; the hands are env.sensor_mounts (left, right)

   Episode: 20 s at 50 Hz. Success: the object, after being lifted, rests within 5 cm of the
   target with both hands off it for 0.2 s. Fail: it falls off the table, or a soft object is
   squashed flat (a pad pushed in all the way) for 0.06 s.

.. py:module:: tactip_mujoco_gym.envs.tactip_gripper

TacGripper: a parallel-jaw gripper whose two fingers are TacTips, on a Cartesian gantry over a table. The task is the humanoid’s (TacHumanoid-pick): squeeze-grasp a soft or rigid object, carry it to a target on the table, put it down. Objects, randomisation, curriculum, reward, success and failure are all shared with it (see tactip_humanoid.py); only the robot differs.

::

       env = gym.make("TacGripper-pick", obs_modes=["tactile", "object"])

   Robot: the gripper hangs from a gantry that moves it in x, y, z and turns it about the
   vertical (stiff position servos, gravity compensated). Its two fingers slide toward each
   other, each a position servo with a force limit (FINGER_FORCE) so a closed command squeezes.
   The TacTips face each other with their tips on the grasp line; the frame around them is
   sized from the mounted sensor, so a different sensor_xml gets a gripper that fits it.

   Actions (5, in [-1, 1], low-pass filtered): grasp centre x, y, z (velocity, world frame),
   grasp width (velocity: negative closes), grasp yaw (turn rate, up to +-GRASP_YAW_MAX).
   The width command may sit at most SQUEEZE_MAX inside the measured gap between the tips,
   which bounds the grip force.

   Observation inputs (obs_modes); proprioception is always included:
       proprio     both tips (world), how far each lags its command, the filtered action, the
                   target, grasp yaw, whether the object has been lifted
       object, privileged, tactile, tactile_image as on TacHumanoid-pick; vision: "overhead"
   reset(options=...): "object", "stiffness", "mass", "friction", "yaw", "level".
   ScriptedPicker (tactip_humanoid.py) drives this gripper too.

Cartesian rig¶

.. py:module:: tactip_mujoco_gym.envs.tactile_rig

TacRig: the sensor on a Cartesian test rig (a desktop-CNC frame with the sensor where the spindle would be, after github.com/shepai/Rig-controller), over a texture block of the 3D Printable Tactile Dataset in its 3D-printed holder.

::

       env = gym.make("TacRig-texture", obs_modes=["tactile"])           # identify the texture
       env = gym.make("TacRig-v0", textures=[1, 2, 3])                   # the rig, no task
       data = press_grid(gym.make("TacRig-v0"))                          # the paper's protocol

   The rig: the sensor rides on three stepper-driven axes, x (front-back), y (left-right, the
   gantry carriage) and z (up-down), each a stiff position servo with a force limit (a stepper
   stalls). The block sits in the holder's pocket on the plate; the plate can be tilted (the
   rig's a axis) by a set angle per episode: reset option "tilt" (rad) or TILT_RANGE. On the
   real rig the plate carries the x travel; here the sensor does, which is the same motion
   relative to the block (MuJoCo heightfields have to be static, and the block is one).

   Blocks (textures.py): the six dataset textures by default (textures=[1..20] or STL files),
   29.3 x 30 mm (BLOCK_MM), 7 mm tall, from the generator's equations as a heightfield
   (TEXTURE_RES_MM between nodes). PRINT_BLUR_MM / PRINT_NOISE_MM imitate a printer's
   smoothing and roughness (drawn per episode). The holder is the dataset's
   Holder_textures.stl, measured: a 31.1 x 30 mm pocket 5.8 mm deep, so a block stands about
   1.2 mm proud of the rim.

   Actions in [-1, 1] (low-pass filtered, ACTION_SMOOTHING): sensor velocity along x, y, z
   (AXIS_SPEED at full command). TacRig-texture adds a decision: see TacRigTexture.

   Observation inputs (obs_modes); proprioception is always included:
       proprio        axis positions (scaled to their travel), command lead over each axis,
                      the filtered action
       force          the plate's force sensor: normal force between sensor and block / holder
                      (N / F_REF)
       privileged     which texture (one-hot), the tip over the block (cm from its centre), the
                      tip's height above the surface under it (cm, negative = pressed in), tilt
       tactile, tactile_image, vision ("rigcam"), + readouts added with sensors={...}
   reset(options=...): "texture" (an entry of env.textures), "start" (x, y in mm from the
   block centre), "tilt" (rad).
