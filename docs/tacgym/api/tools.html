Experiments and training¶

.. py:module:: tactip_mujoco_gym.experiment

Experiment configs: one YAML / JSON file says what is being tested - the task, the robot’s options, the sensor hardware, the readouts, which inputs the policy gets, how they are fused, and how to train - so a comparison is a set of files (or variants in one file), not edits to code.

::

       python -m tactip_mujoco_gym train configs/peg_sensing.yaml               # every variant
       python -m tactip_mujoco_gym train configs/peg_sensing.yaml --variant tactile
       python -m tactip_mujoco_gym train configs/peg_sensing.yaml --dry-run     # show, don't run
       python -m tactip_mujoco_gym evaluate configs/peg_sensing.yaml --variant tactile

   Keys (all optional except env):

       name           model / log name (default: <env>_<inputs>); variants append _<variant>
       description    free text
       env            task id (python -m tactip_mujoco_gym list)
       env_kwargs     task / robot options, e.g. {start_touching: false} or {feet: proxy}
       sensor_xml     sensor hardware: a registered name ("tactip"), a standalone MJCF file
       sensor_stiffness   skin stiffness multiplier
       sensors        readouts: {key: spec}; a spec is a registered name, "module:Class", or
                      {type: ..., <arguments>}; {width: 96} without a type tweaks the default;
                      null removes it
       obs_modes      inputs the policy gets: [tactile, vision] (proprioception always included)
       obs_format     flat | dict
       overrides      {CONSTANT: value} for the env's class constants
       policy         {encoders: null | scratch | <checkpoint>, freeze_encoders: true}
       train          {algo: PPO, steps: 3000000, n_envs: 8, seed: 0, algo_kwargs: {...},
                       record_video: true, video_every_percent: 5, video_seconds: 7,
                       checkpoint_every: 500000}
       evaluate       {episodes: 50, deterministic: true, seed: 1000}
       imports        modules to import first (e.g. the module that registers your readout)
       variants       {name: {<any keys above>}} merged over the base (dicts merge, the rest
                      replaces), one run each

   In Python:

       from tactip_mujoco_gym.experiment import load_config, make_env, train
       cfg = load_config("configs/peg_sensing.yaml")
       env = make_env(cfg, variant="tactile")

.. py:module:: tactip_mujoco_gym.RL_BASE

Training / evaluation helpers for every task (Stable-Baselines3). Config files drive these through experiment.py (python -m tactip_mujoco_gym train ).

::

       run(ENV_NAME, MODEL_NAME, LOG_NAME, STEPS)                     # privileged obs, PPO
       run(ENV_NAME, MODEL_NAME, LOG_NAME, STEPS,
           obs_modes={"vision": True, "tactile": True, "privileged": False})   # pick the inputs
       run(ENV_NAME, MODEL_NAME, LOG_NAME, STEPS, obs_modes=["tactile"],
           env_kwargs={"sensor_xml": "my_sensor.xml", "sensors": {"tactile": {"clip": 10}}})
       run(ENV_NAME, MODEL_NAME, LOG_NAME, STEPS, obs_format="dict")  # one key per input (fusion)
       run(ENV_NAME, MODEL_NAME, LOG_NAME, STEPS, obs_modes={"vision": True, "tactile": True},
           encoders="encoders/vt.pt")       # pretrained encoders + MLP (see train_encoders.py)
       run(ENV_NAME, MODEL_NAME, LOG_NAME, STEPS, algo="SAC")         # more sample-efficient
       evaluate(ENV_NAME, MODEL_NAME)                                 # success rate, no viewer
       visualise(ENV_NAME, MODEL_NAME)                                # MuJoCo viewer

   What run() saves (both in logs/<LOG_NAME>/ and models/):
       <MODEL_NAME>.zip                  the policy
       <MODEL_NAME>_vecnormalize.pkl     observation statistics - the policy is useless without them
       <MODEL_NAME>.json                 env name / kwargs / algo, so evaluate() and visualise()
                                         rebuild exactly the same environment

.. py:function:: policy_for(obs_space, own_encoders=False, encoded_keys=None) :module: tactip_mujoco_gym.RL_BASE

MlpPolicy for a flat vector. For a dict: MultiInputPolicy (SB3 runs a CNN on image keys and an MLP on the rest, then concatenates the features), with images kept out of VecNormalize; with own_encoders, the encoded inputs (encoded_keys, default tactile and vision) are also left to the encoders. Returns (policy name, keys to normalise or None, has images).

Default: privileged only. privileged : earlier shortcut (True = privileged only, False = tactile only); ignored when obs_modes is given obs_format : “flat” (one long vector, MlpPolicy) or “dict” (one key per input, MultiInputPolicy: CNN on the camera image, MLP on the rest) env_kwargs : extra constructor args, e.g. {“spawn_yaw”: 0.5} for TacArm-shape encoders : path to a checkpoint from train_encoders.py -> VisuoTactilePolicy: pretrained tactile / vision encoders, then the MLP heads (implies obs_format=”dict”). “scratch” = the same networks without pretraining (baseline). freeze_encoders : keep the pretrained encoder weights fixed during RL (default True) callbacks : extra SB3 callbacks (e.g. logging task-specific info, see quadruped_walk.py)

.. py:module:: tactip_mujoco_gym.vt_encoders

Visuo-tactile encoders, and the policy that uses them.

::

       TactileEncoder         MLP on the tactip marker vector (displacement + change, in mm).
                              Carries its own input normalisation, fitted on the training data
                              and saved with the weights, so VecNormalize must leave "tactile" alone.
       VisionEncoder          small CNN on the hand-camera image: float, channels first, [0, 1]
                              (exactly what SB3 hands a policy for a uint8 image observation).
       VisuoTactileExtractor  SB3 features extractor for dict observations: tactile -> TactileEncoder,
                              vision -> VisionEncoder, everything else (proprio, privileged, events)
                              passed straight through; the results are concatenated. Which keys
                              get which encoder is `encoder_keys` ({key: "mlp" | "cnn"}): RL_BASE
                              takes it from the env (env.obs_modalities), so a readout you add
                              (e.g. "tactile_image", or your own sensor) gets an encoder too.
       VisuoTactilePolicy     PPO policy = VisuoTactileExtractor + MLP actor and critic heads.

   Pretrained weights come from train_encoders.py. Pass encoder_path=None for the same networks
   trained from scratch (a useful baseline).

   Note: SB3's PPO policies re-initialise every Linear / Conv2d layer of the features extractor
   (orthogonal init) after building it, which would silently erase pretrained weights.
   VisuoTactilePolicy reloads them after SB3 has finished building, so use it (not
   "MultiInputPolicy" + extractor kwargs) with PPO. SAC does not re-initialise, so there the
   extractor can be passed through policy_kwargs (see sac_policy_kwargs).
